# INC-011 - Ancillary catalogue silently empty for three days

**Date:** 2026-07-08
**Duration:** 3 days
**Severity:** SEV-3
**Author:** Ancillaries team

## Summary

Seat upgrades, extra baggage and lounge access disappeared from the booking
flow for a subset of routes. No error appeared anywhere. Revenue reporting
found it.

## Timeline

- **July 5** - Catalogue provider rotates a credential without notice.
- **July 5–8** - Ancillary attach rate on affected routes drops to zero.
- **July 8** - Weekly revenue review flags the drop.
- **July 8, 14:00** - Cause identified within twenty minutes of looking.

## Impact

Three days of lost ancillary revenue on roughly a fifth of routes. The exact
figure was material enough to be reported upward.

## What went wrong

`getAncillaryCatalogue` wraps the provider call in a try/catch. The catch logs
the error to the console and returns an empty array.

An empty catalogue is a legitimate state - some routes genuinely offer no
ancillaries - so the caller had no way to distinguish "nothing available" from
"the call failed". The booking flow rendered an empty section, exactly as it
would for a route with no offers.

There were no errors in the monitoring dashboard because nothing threw. The
console log went to a stream nobody watches. From every angle the system looked
healthy.

## Resolution

The catch now rethrows a typed failure. The booking flow distinguishes an empty
catalogue from an unavailable one and reports the latter.

## Action items

- A catch block must rethrow, return a typed failure, or emit a structured
  event. Logging alone is not handling.
- Alert on ancillary attach rate dropping to zero on any route.
