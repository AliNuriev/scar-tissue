# INC-008 - Last passenger dropped from manifest exports

**Date:** 2026-05-20
**Duration:** 4 days (undetected)
**Severity:** SEV-2
**Author:** Operations tooling

## Summary

Crew manifest exports omitted the final passenger on every page. The gap went
unnoticed for four days because manifests are usually cross-checked against a
separate system only at the gate.

## Timeline

- **May 16** - Pagination introduced to the manifest export to handle wide-body
  aircraft.
- **May 20** - Gate agent reports a passenger present on board but absent from
  the printed manifest.
- **May 20, 16:00** - Confirmed across all exports since the 16th.

## Impact

Between one and four passengers missing per manifest across roughly 600
flights. No safety incident occurred, but the manifest is a regulatory
document and the gap had to be reported.

## What went wrong

The paging helper slices the passenger array using `start` and
`start + pageSize - 1` as the end index, and the slice call treats the end
index as exclusive.

The result is that the last element of every page is silently dropped. For a
single-page manifest of exactly one passenger, the export came back empty.

Tests covered a list of 100 passengers with a page size of 10 and asserted that
ten pages were produced. They did not assert on the total number of rows across
all pages, so the missing entries were invisible.

## Resolution

Corrected the slice bounds and added an assertion that the concatenation of all
pages equals the original collection.

## Action items

- Every paging test must assert on total count, not page count.
- Cover the empty and single-element cases explicitly.
