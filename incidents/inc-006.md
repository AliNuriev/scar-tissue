# INC-006 - Loyalty points credited twice on retried bookings

**Date:** 2026-06-11
**Duration:** 2h
**Severity:** SEV-2
**Author:** Loyalty team

## Summary

Some members received double loyalty points for a single booking. The finance
reconciliation caught it, not us.

## Timeline

- **10:05** - Mobile client ships a build with an aggressive retry on timeout.
- **10:05–11:50** — Duplicate credits accumulate unnoticed.
- **11:52** - Finance flags a mismatch between bookings and points issued.
- **12:10** - Points crediting paused.

## Impact

312 members over-credited by a combined 480,000 points. Reversal was decided
against on customer-goodwill grounds, so the points were written off.

## What went wrong

`creditPoints` loads the member's balance record, checks whether a credit for
this booking reference already exists in the ledger, and if not appends the
entry and saves the new balance.

When the mobile client retried a request that had actually succeeded but timed
out, two identical requests arrived within the same second. Both loaded the
balance, both found no existing ledger entry because neither had written one
yet, and both appended.

This is the same shape as the seat assignment failure in April, in a completely
different part of the codebase, written by a different team, four months later.
The postmortem for INC-001 exists and is thorough. Nobody on the loyalty team
had read it.

## Resolution

Added a unique constraint on the booking reference in the ledger and moved the
credit into a single atomic operation.
